# Database Rules

**Status:** Binding. Schema changes, queries, and DB access must follow these rules.

## 1. Engine and hosting

- **Supabase (free tier) hosts Postgres** for the real app (`DATABASE_URL`). Always use the **session pooler** URI (`*.pooler.supabase.com:5432`): it works over IPv4, supports `LISTEN/NOTIFY` (the job queue needs it), and supports asyncpg prepared statements. **Never use the transaction pooler (port `6543`).** The engine refuses a URL with port `6543`.
- The app uses plain Postgres features only, with no Supabase client SDK, auth, storage, or RLS. Supabase is just the Postgres host, so the app can move to any Postgres.
- Supabase exposes tables through its auto-generated REST API. The first migration runs `REVOKE ALL ON ALL TABLES IN SCHEMA public FROM anon, authenticated` and enables RLS on every table with no policies, so the public API can read nothing.
- **No paid add-ons** (no paid Supabase tier, no managed Redis, no paid queue). The job queue lives in Postgres.
- **Tests run against a separate Supabase project** (`TEST_DATABASE_URL`), never SQLite and never the real database. SQLite hides JSONB, `SKIP LOCKED`, partial indexes, and `CHECK` behaviour. `conftest.py` aborts the whole run if `TEST_DATABASE_URL` is unset or equals `DATABASE_URL`, because the tests drop and recreate the schema.

## 2. Access layer

- **SQLAlchemy 2.0 async + asyncpg.** One `AsyncEngine` is created in the FastAPI lifespan and disposed on shutdown. Never create an engine per request.
- **Pool:** a hard per-process cap (`pool_size=<cap>`, `max_overflow=0`), `pool_pre_ping=True`, `pool_recycle=1800`. The Supabase session pooler allows only **15** client connections per project across all processes (`EMAXCONNSESSION` beyond that), so the caps must add up to less: API 4, worker `concurrency + 1` (+1 LISTEN), scheduler 1 — 14 for the `dev.sh` layout. A test checks the sum. A new process or a higher concurrency needs a new budget.
- **Sessions:** `async_sessionmaker(engine, expire_on_commit=False)`. Request handlers get a session through the `get_session` dependency. Workers open one session per job.
- **Transactions are short.** Never hold a transaction open across a network call to GitHub, Gemini, LinkedIn, or a subprocess. Read what you need, commit or close, do the slow call, then open a new transaction to write the results.
- **All ORM models live in `src/linkedbuddy/db/models.py`.** The schema is one unit, and Alembic autogenerate needs every model imported in one place.
- **No raw SQL string building.** Use ORM or Core expressions. Use `text()` only with bound parameters (see SECURITY.md 4.2).

## 3. Migrations

- **Alembic is the only way to change the schema.** Never call `create_all()` outside tests.
- **One migration per logical change**, named `YYYYMMDD_HHMM_<slug>.py`. Review autogenerated output by hand, because autogenerate misses `CHECK` constraints, partial indexes, and server defaults.
- **Every migration has a working `downgrade()`.** Tests run `upgrade head` → `downgrade base` → `upgrade head` once in CI.
- **Never edit a migration that has run on a database you care about.** Write a new one.
- **Adding a `NOT NULL` column to a table with data** is two steps: add it nullable with a default, backfill, then set `NOT NULL`.

## 4. Conventions

| Thing | Rule |
|---|---|
| Primary keys | `uuid` with `server_default=text("gen_random_uuid()")`, except natural keys noted below |
| Timestamps | `timestamptz`, `server_default=now()`. Store UTC and never naive datetimes |
| Enums | `text` + `CHECK (col IN (...))`, mirrored by a Python `Literal` or `StrEnum`. No Postgres `ENUM` types, because they are painful to migrate |
| Flexible fields | `jsonb` only for data never filtered on (stats, scores, segments, metrics). Anything used in `WHERE` or `ORDER BY` is a real column |
| Secrets | `bytea` columns ending in `_enc`, Fernet-encrypted (SECURITY.md 1.3) |
| Foreign keys | Always declared. `ON DELETE CASCADE` for owned children, `SET NULL` for optional links |
| Names | `snake_case`, plural table names, indexes named `ix_<table>_<cols>`, uniques `uq_<table>_<cols>` |

## 5. Tenancy

**Single owner.** There is no `users` table and no `user_id` column. `settings` is a singleton row (`id = 1`, `CHECK (id = 1)`). Going multi-user later is a planned migration (add `users`, then add `user_id` to `connections`, `settings`, `repos`, `series`, and `sessions`). Do not add `user_id` speculatively now.

## 7. Query rules (speed)

1. **Every list endpoint is paginated** with keyset pagination (`WHERE (created_at, id) < (:c, :i) ORDER BY created_at DESC, id DESC LIMIT :n`), with a default of 50 and a max of 200. No `OFFSET` beyond the first page.
2. **List queries select only the columns the list needs.** The inbox never loads `context_json`, `rating_json`, or draft bodies.
3. **No N+1.** Load relationships with `selectinload()` or a join. Relationships default to `lazy="raise"`, so an accidental lazy load fails loudly in tests.
4. **Every `WHERE` or `ORDER BY` pattern used by an endpoint or worker has an index** listed in section 6. Add the index in the same migration as the query that needs it.
5. **Upserts use `INSERT … ON CONFLICT`** (`sqlalchemy.dialects.postgresql.insert`). Ingestion relies on this for idempotency: `commits` by `(repo_id, sha)`, `events` by `dedupe_key`, `repos` by `github_repo_id`.
6. **Bulk writes are batched.** Insert commits for a poll in one statement, not in a loop.
7. **Slow query guard:** in dev, log any statement over 100 ms (SQLAlchemy `before/after_cursor_execute` events). Treat a logged slow query as a bug.

## 8. Job queue in Postgres

- **Claim** with one statement:
  `UPDATE jobs SET status='running', locked_at=now(), attempts=attempts+1 WHERE id = (SELECT id FROM jobs WHERE status='queued' AND kind = ANY(:kinds) AND run_after <= now() ORDER BY run_after LIMIT 1 FOR UPDATE SKIP LOCKED) RETURNING *`.
- **Wake-up** uses `NOTIFY jobs_<kind>` on enqueue and `LISTEN` in the worker, with a 5 s poll as a fallback. Workers never busy-loop.
- **Stale locks:** a job in `running` with `locked_at < now() - interval '10 minutes'` is reset to `queued` by the scheduler (or marked `failed` when `attempts >= max_attempts`).
- **Retention:** `done` jobs are deleted after 7 days and `failed` jobs after 30 days, by the scheduler.

## 9. Data retention

- `events.context_json` is set to `NULL` 7 days after the event's newest draft, or 7 days after it was built for an event that was never drafted (SECURITY.md 6.9).
- `sessions` past `expires_at` are deleted hourly.
- `posts`, `drafts`, and `decisions` are kept indefinitely. They are the calibration dataset.
- Deleting a repo cascades to its commits, events, drafts, and media rows. Media files are removed from disk by the same service call, not by a trigger.

## 10. Checklist for every schema change

- [ ] Alembic migration with a working downgrade
- [ ] `CHECK` constraints mirror the Python enums
- [ ] An index exists for every new filter or sort pattern
- [ ] New relationships declared `lazy="raise"`
- [ ] No secret stored unencrypted
- [ ] Tests run against Postgres and pass after `downgrade base` → `upgrade head`
